Verkot ja volyymit

< Takaisin etusivulle

1. Mikä Docker-verkko on?

Docker-verkko yhdistää kontteja toisiinsa. Samassa verkossa olevat kontit voivat ottaa yhteyden toisiinsa palvelun nimellä, esimerkiksi database tai notes-api. Docker huolehtii verkon sisäisestä nimenselvityksestä, joten konttien IP-osoitteita ei tarvitse kirjoittaa Compose-tiedostoon.

Verkko myös rajaa liikennettä. Kontti voi keskustella vain niiden palveluiden kanssa, joihin se on liitetty. Tämä auttaa rakentamaan ympäristön, jossa julkinen reititin, sovelluspalvelut ja tietokanta eivät kaikki ole samassa verkossa.

2. Verkkojen käyttö Docker Composessa

Compose luo projektin verkot automaattisesti, kun pino käynnistetään. Palvelu liitetään verkkoon palvelun alla olevalla networks-määrityksellä:

services:
      notes-api:
    networks:
      - frontend-network
      - backend-network

networks:
  frontend-network:
    driver: bridge

Yksi palvelu voi kuulua useaan verkkoon. Se toimii tällöin verkkojen välisenä yhteyspisteenä, mutta muut palvelut voivat nähdä sen vain oman yhteisen verkkonsa kautta. Compose-verkon tavallinen bridge-ajuri sopii saman Docker-isännän konttien yhdistämiseen.

Verkkoon liitetty palvelu löytyy nimellä, joka on määritelty kohdassa services. Esimerkiksi http://notes-api:3000 tarkoittaa porttia 3000 palvelussa nimeltä notes-api. Porttia ei tarvitse julkaista isännälle, jotta toinen kontti voi käyttää sitä.

3. Tämän projektin verkot

Tässä projektissa on kaksi verkkoa, joilla erotetaan käyttöliittymän liikenne tietokannan taustaverkosta:

VerkkoPalvelutTarkoitus
frontend-network proxy, web, notes-api Välittää selaimen, proxyn, staattisen web-palvelun ja API:n välistä liikennettä.
backend-network notes-api, database Mahdollistaa API:n ja PostgreSQL:n välisen yhteyden. Verkko on ulkoiselta liikenteeltä rajattu.

notes-api kuuluu molempiin verkkoihin. Se voi vastaanottaa API-pyynnöt frontend-network-verkosta ja ottaa tietokantayhteyden backend-network-verkossa. database kuuluu vain backend-verkkoon, joten sitä ei ole liitetty suoraan proxyyn tai web-palveluun.

4. Frontend-verkon liikenne

Proxy on ainoa palvelu, joka julkaisee portin isäntäkoneelle:

proxy:
  ports:
    - "80:80"
  networks:
    - frontend-network

Proxyn nginx-konfiguraatio käyttää Compose-palveluiden nimiä:

location / {
    proxy_pass http://web:80;
}

location /api/ {
    proxy_pass http://notes-api:3000/api/;
}

Kun selain pyytää http://localhost/, pyyntö saapuu proxylle. Proxy löytää web-kontin Dockerin sisäisen DNS:n avulla. Kun selain käyttää muistiinpanojen API:a, /api/-pyyntö ohjataan samalla tavalla notes-api-palvelulle.

5. Backend-verkon eristys

Backend-verkko on määritelty asetuksella internal: true:

networks:
  backend-network:
    internal: true

Se tarkoittaa, että verkko on tarkoitettu Dockerin sisäiseen liikenteeseen eikä sitä julkaista suoraan ulkoiseen verkkoon. Tietokannalle ei ole määritelty ports-kohtaa, joten isäntäkoneen porttia ei avata PostgreSQL:lle. API käyttää tietokantaa sisäisesti osoitteella database:5432.

internal: true ei tarkoita, että verkon palvelut olisivat toisiltaan piilossa: notes-api ja database voivat edelleen keskustella keskenään. Se rajoittaa verkon ulkoista yhteyttä. Turvallisuus riippuu lisäksi sovelluksen asetuksista, tunnuksista ja siitä, mitä muita verkkoja palveluihin liitetään.

6. Verkkojen tarkastaminen komennoilla

# Listaa Dockerin verkot
docker network ls

# Näytä yhden verkon kontit ja asetukset
docker network inspect docker-rojekti_frontend-network

# Tarkista Compose-palveluiden tila
docker compose ps

# Tarkista yhteys API-kontista tietokantaan
docker compose exec notes-api node -e \
  "require('dns').lookup('database', console.log)"

Compose lisää verkon nimeen yleensä projektin nimen etuliitteen, kuten docker-rojekti_. Tarkka nimi kannattaa tarkistaa komennolla docker network ls, jos projektin nimeä on muutettu.

7. Mikä Docker-volyymi on?

Kontin oma tiedostojärjestelmä on sidoksissa kontin elinkaareen. Jos kontti poistetaan, sen sisälle kirjoitetut muutokset voivat kadota. Volyymi tallentaa valitut tiedostot kontin ulkopuolelle, jolloin uusi kontti voi käyttää samaa dataa.

Volyymit sopivat erityisesti tietokantojen dataan. Ne eivät ole sama asia kuin image: image sisältää sovelluksen lähtötiedostot, kun taas volyymi sisältää käytön aikana syntyvää dataa. Volyymi ei myöskään ole automaattinen varmuuskopio.

8. Nimetty volyymi tässä projektissa

PostgreSQL käyttää Composen nimettyä volyymiä:

services:
  database:
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Vasemmanpuoleinen pgdata on Dockerin hallitseman volyymin nimi. Oikeanpuoleinen /var/lib/postgresql/data on PostgreSQL:n datakansio kontin sisällä. Kun database-kontti luodaan uudelleen, PostgreSQL löytää aiemmin tallennetut taulut ja muistiinpanot samasta volyymistä.

docker compose down poistaa kontit ja verkot, mutta säilyttää normaalisti nimetyn volyymin. Siksi tietokannan data säilyy tavallisen uudelleenkäynnistyksen jälkeen. Komento docker compose down -v poistaa myös volyymin, joten sitä käytettäessä tämän demon muistiinpanot häviävät.

9. Bind mount ja volyymi ovat eri asioita

Compose-tiedostossa on myös bind mount proxyn nginx-konfiguraatiolle:

proxy:
  volumes:
    - ./proxy/nginx.conf:/etc/nginx/conf.d/default.conf:ro

Tässä lähdekoneen tiedosto ./proxy/nginx.conf liitetään suoraan kontin polkuun /etc/nginx/conf.d/default.conf. Tämä ei ole nimetty Docker-volyymi, vaan bind mount, jossa käytetään projektin omaa tiedostoa.

  • Nimetty volyymi, kuten pgdata, on Dockerin hallitsema ja sopii pysyvälle sovellusdatalle.
  • Bind mount käyttää tiettyä isäntäkoneen tiedostoa tai kansiota ja sopii esimerkiksi konfiguraatioon kehityksen aikana.
  • :ro tekee nginx-konfiguraation kontissa vain luku -tilaan, joten proxy ei voi muokata projektin tiedostoa.

10. Volyymien tarkastaminen ja siivoaminen

# Listaa nimetyt Docker-volyymit
docker volume ls

# Näytä volyymin sijainti ja käyttö
docker volume inspect docker-rojekti_pgdata

# Näytä Compose-palveluiden volyymit
docker compose config

# Poista käyttämätön volyymi (tarkista nimi ensin)
docker volume rm volyymin_nimi

Volyymiä ei pidä poistaa sokkona, jos siinä voi olla tärkeää dataa. Tämän projektin pgdata-volyymiä käytetään PostgreSQL:n pysyvään dataan, joten ennen poistamista kannattaa ottaa varmuuskopio tai varmistaa, että demon tiedot saa luoda uudelleen.

11. Tiivistelmä

  • Docker-verkot yhdistävät kontteja ja tarjoavat palvelunimillä toimivan sisäisen DNS:n.
  • frontend-network yhdistää proxyn, web-palvelun ja API:n.
  • backend-network yhdistää API:n ja tietokannan, ja internal: true rajaa verkon ulkoista liikennettä.
  • pgdata säilyttää PostgreSQL:n datan konttien uudelleenluonnin yli.
  • Bind mountilla projektin nginx-konfiguraatio tuodaan proxy-konttiin vain luku -tilassa.
  • Verkot ja volyymit poistuvat eri tavalla: down poistaa kontit ja verkot, mutta ei yleensä nimettyjä volyymejä.

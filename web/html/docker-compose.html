Docker Compose

< Takaisin etusivulle

1. Mikä Docker Compose on?

Docker Compose on tapa kuvata usean kontin muodostama sovellus yhdessä YAML-tiedostossa. Yhdessä palvelussa voi olla esimerkiksi käyttöliittymä, toisessa API ja kolmannessa tietokanta. Compose luo näille palveluille yhteisen ympäristön: kontit, verkot, porttiohjaukset, volyymit ja käynnistysriippuvuudet.

Compose ei ole uusi konttityyppi, vaan työkalu konttien hallintaan. docker-compose.yaml kertoo, miten jo olemassa olevat imaget käynnistetään ja miten projektin omat imaget rakennetaan.

2. Ensimmäinen käynnistys

Kun komennot suoritetaan tämän repositorion juurikansiosta, koko pino voidaan rakentaa ja käynnistää näin:

# Rakenna omat imaget ja käynnistä palvelut taustalle
docker compose up --build -d

# Näytä palveluiden tila
docker compose ps

# Katso kaikkien palveluiden lokit
docker compose logs -f

Lippu --build rakentaa uudelleen web- ja notes-api-palveluiden imaget. -d jättää kontit käyntiin taustalle. Selain avaa sivun portin 80 kautta osoitteesta http://localhost.

3. Build ja konttien pakotettu uudelleenluonti

Jos haluat varmistaa, että imaget rakennetaan uudelleen ja kontit luodaan varmasti uudestaan, käytä komentoa:

docker compose up --build --force-recreate

Komennon osat tarkoittavat seuraavaa:

  • up käynnistää Compose-tiedoston palvelut.
  • --build rakentaa build-määrityksellä tehdyt imaget ennen käynnistystä.
  • --force-recreate poistaa nykyiset palvelukontit ja luo ne uudelleen, vaikka Compose ei havaitsisi asetuksissa muutosta.

Tätä komentoa voi tarvita esimerkiksi silloin, kun Dockerfile, asennettavat riippuvuudet tai ympäristömuuttujat ovat muuttuneet ja haluat varmasti käynnistää uuden version kaikissa konteissa. Se on myös hyödyllinen vianmäärityksessä, jos vanha kontti käyttää epähuomiossa vanhaa imagea tai vanhoja konttiasetuksia.

Komento ei poista nimettyä pgdata-volyymia, joten PostgreSQL:n data säilyy normaalisti. Konttien uudelleenluonti kuitenkin pysäyttää hetkeksi palvelut, joten tuotannossa komento kannattaa ajaa suunnitellun huoltokatkon yhteydessä. Jos haluat lisäksi poistaa volyymin ja tietokannan datan, siihen tarvitaan erikseen docker compose down -v.

4. Tämän projektin palvelut

Nykyinen docker-compose.yaml määrittelee neljä palvelua. Lisäksi siinä on yksi nimetty volyymi ja kaksi käyttäjän määrittelemää verkkoa.

PalveluTehtäväMiten se syntyy?
web Tarjoaa staattiset HTML-, CSS- ja JavaScript-tiedostot nginxillä. Rakennetaan kansiosta ./web.
proxy On ulospäin näkyvä reititin. Se välittää sivupyynnöt web-palvelulle ja /api/-pyynnöt API:lle. Käyttää imagea nginx:alpine ja projektin nginx-konfiguraatiota.
notes-api Node.js- ja Express-sovellus, joka tarjoaa muistiinpanojen rajapinnan. Rakennetaan kansiosta ./notes-api.
database PostgreSQL-tietokanta, johon API tallentaa muistiinpanot. Käyttää imagea postgres:17-alpine.

Palvelun nimi toimii Composen sisäisenä DNS-nimenä. Siksi API voi ottaa yhteyden tietokantaan osoitteella database:5432, eikä tietokannan IP-osoitetta tarvitse tietää etukäteen.

5. Rakentaminen ja imaget

web-palvelun kohta build: ./web käyttää rakennuskontekstina web-kansiota. Sen Dockerfile kopioi HTML-sisällön nginxin tarjoiltavaksi. notes-api rakennetaan vastaavasti kansiosta ./notes-api; sen Dockerfile asentaa Node-riippuvuudet ja käynnistää server.js-tiedoston.

services:
  web:
    build: ./web

  notes-api:
    build: ./notes-api

  database:
    image: postgres:17-alpine

build tarkoittaa, että image tehdään projektin Dockerfilesta. image tarkoittaa, että Compose hakee tai käyttää valmista imagea. Molemmat palvelut voivat esiintyä samassa Compose-tiedostossa.

6. Reititys verkkojen avulla

Palvelut on jaettu kahteen verkkoon:

  • frontend-network yhdistää proxyn, web-palvelun ja API:n.
  • backend-network yhdistää API:n ja tietokannan. Verkko on määritelty asetuksella internal: true, joten sitä ei ole tarkoitettu ulkoiseen liikenteeseen.

proxy julkaisee ainoana palveluna isännän portin:

ports:
  - "80:80"

Proxyn nginx-konfiguraatio ohjaa pyynnöt palvelunimillä:

location / {
    proxy_pass http://web:80;
}

location /api/ {
    proxy_pass http://notes-api:3000/api/;
}

Selain ottaa yhteyden vain proxyyn. Web-palvelua, API:a tai tietokantaa ei tarvitse julkaista suoraan isännän porteilla.

7. Ympäristömuuttujat ja tietokannan pysyvyys

notes-api saa tietokantayhteyden asetukset ympäristömuuttujina. Esimerkiksi DB_HOST: database viittaa Compose-palveluun nimeltä database. PostgreSQL saa samat tunnistetiedot muuttujilla POSTGRES_USER, POSTGRES_PASSWORD ja POSTGRES_DB.

environment:
  DB_HOST: database
  DB_PORT: 5432
  DB_NAME: demo_notes

Palvelu database liittää nimetyn volyymin tietokannan datakansioon:

volumes:
  - pgdata:/var/lib/postgresql/data

Volyymi säilyttää PostgreSQL-datan, vaikka tietokantakontti poistetaan ja luodaan uudelleen. Volyymi ei kuitenkaan ole varmuuskopio: demo-tunnukset ja salasanat pitäisi oikeassa tuotannossa siirtää salaisuuksien hallintaan.

8. Käynnistysjärjestys ja healthcheckit

depends_on kertoo, että proxy tarvitsee terveen web-palvelun ja API tarvitsee terveen database-palvelun. Healthcheck tarkistaa, vastaako palvelu oikeasti pyyntöihin; pelkkä kontin käynnistyminen ei vielä tarkoita, että sovellus on valmis.

depends_on:
  database:
    condition: service_healthy

Tietokannan tarkistus käyttää pg_isready-komentoa. Web-palvelun ja API:n tarkistukset käyttävät wget-komentoa, joka kuuluu näiden Alpine-pohjaisten nginx- ja Node-imagejen mukana. API:n healthcheck hakee sovelluksen /health-reitin:

healthcheck:
  test: ["CMD", "wget", "-qO-", "http://127.0.0.1:3000/health"]
  interval: 10s
  timeout: 3s
  retries: 3
  start_period: 5s

API:n server.js määrittelee /health-reitin, joka vastaa onnistuneessa tilanteessa JSON-muodossa. wget palauttaa onnistuneen poistumiskoodin, kun reitti vastaa, joten Compose voi merkitä API-kontin terveeksi. API:n healthcheck kertoo API:n tilan, mutta nykyisessä tiedostossa proxy ei riipu suoraan API:n healthcheckistä; proxyn käynnistyminen odottaa vain web-palvelun olevan terve.

9. Hyödylliset ylläpitokomennot

# Käynnistä uudelleen ilman uutta buildia
docker compose restart

# Katso yhden palvelun lokit
docker compose logs -f notes-api

# Aja komento käynnissä olevassa kontissa
docker compose exec database pg_isready -U demo_user -d demo_notes

# Pysäytä kontit ja verkot, säilytä volyymi
docker compose down

# Poista myös nimetty volyymi (tietokannan data häviää)
docker compose down -v

docker compose down poistaa Compose-kontit ja verkot, mutta jättää nimetyn pgdata-volyymin talteen. Lippu -v on tuhoisa tietokannan datalle, joten sitä käytetään vain, kun data saa oikeasti poistua.

10. Tiivistelmä

  • Compose kokoaa web-palvelun, proxyn, API:n ja tietokannan yhdeksi ajettavaksi kokonaisuudeksi.
  • Palvelut löytävät toisensa nimillä, kuten web ja database.
  • Vain proxy julkaisee portin 80 ulospäin; verkot rajaavat palveluiden välistä liikennettä.
  • pgdata-volyymi säilyttää tietokannan datan konttien elinkaaren yli.
  • Healthcheck kertoo palvelun valmiudesta, mutta tarkistuksen komennon ja reitin on vastattava käytössä olevaa imagea ja sovellusta.

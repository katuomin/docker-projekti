Kuberneteksen perusteet

< Takaisin etusivulle

1. Mikä Kubernetes (K8s) on?

Kubernetes (tunnetaan myös lyhenteellä K8s) on avoimen lähdekoodin järjestelmä kontitettujen sovellusten automaattiseen käyttöönottoon, skaalaukseen ja hallintaan (konttiorkestraatio).

Kun sovelluksia ajetaan useissa konteissa useilla eri palvelimilla, manuaalinen hallinta käy nopeasti mahdottomaksi. Kubernetes huolehtii automaattisesti konttien sijoittelusta, uudelleenkäynnistyksistä vikatilanteissa sekä liikenteen ohjauksesta.

2. Klusterin perusarkkitehtuuri

Kubernetes-klusteri koostuu kahdesta pääosasta: Control Planesta (ohjaustaso) ja Worker Nodeista (työsolmut).

  • Control Plane: Hallitsee klusterin tilaa. Se sisältää komponentit kuten kube-apiserver (rajapinta kaikille komennoille), etcd (klusterin hajautettu tietokanta) ja kube-scheduler (päättää millä nodella kukin pod ajetaan).
  • Worker Node: Palvelin (fyysinen tai virtuaalikone), jossa itse sovelluskontit ajetaan. Nodella toimii kubelet (agentti, joka kommunikoi apiserverin kanssa) sekä kube-proxy (verkkoliikenteen reititys).

3. Pod – Pienin ajettava yksikkö

Kubernetes ei aja kontteja suoraan, vaan käärii ne Podiin. Pod edustaa yhtä sovellusprosessin instanssia ja se voi sisältää yhden tai useamman toisiinsa tiukasti liittyvän kontin, jotka jakavat saman verkko-IP:n ja tallennustilan.

apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: web
spec:
  containers:
    - name: nginx
      image: nginx:1.25
      ports:
        - containerPort: 80

Podit ovat luonteeltaan väliaikaisia: jos pod tuhoutuu tai node kaatuu, pod ei palaa takaisin samana, vaan tilalle luodaan uusi.

4. Deployment – Hallintaa ja itseparantuvuutta

Käytännössä podeja ei juuri koskaan luoda suoraan, vaan niiden elinkaarta ohjataan Deployment-resurssilla. Deployment määrittelee halutun tilan (esim. montako kopiota podista halutaan ajaa) ja huolehtii automaattisesti päivityksistä ilman käyttökatkoa (rolling updates).

apiVersion: apps/v1
kind: Deployment
metadata:
  name: notes-api-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: notes-api
  template:
    metadata:
      labels:
        app: notes-api
    spec:
      containers:
        - name: notes-api
          image: notes-api:latest
          ports:
            - containerPort: 3000

Jos yksi podeista kaatuu, Deploymentin alla oleva ReplicaSet luo automaattisesti uuden tilalle, jotta haluttu määrä (replicas: 3) säilyy.

5. Service – Liikenteen reititys podeille

Koska podit saavat dynaamiset IP-osoitteet, jotka muuttuvat niiden käynnistyessä uudelleen, tarvitaan Service. Service toimii kiinteänä osoitteena ja kuormantasaajana pod-joukolle.

  • ClusterIP: Oletustyyppi. Palvelu näkyy vain klusterin sisäverkossa.
  • NodePort: Avaa saman portin kaikille klusterin nodeille, jolloin palveluun pääsee käsiksi ulkopuolelta noden IP-osoitteella.
  • LoadBalancer: Pyytää pilvipalvelulta (AWS, Azure, GCP) ulkoisen kuormantasaajan ja julkisen IP-osoitteen.
apiVersion: v1
kind: Service
metadata:
  name: notes-api-service
spec:
  type: ClusterIP
  selector:
    app: notes-api
  ports:
    - port: 80
      targetPort: 3000

6. ConfigMap ja Secret – Asetusten eriyttäminen

Sovelluksen asetukset ja salaisuudet pidetään erillään kontti-imageista käyttämällä ConfigMap- ja Secret-resursseja.

Esimerkki konfiguraatiosta (ConfigMap):

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: "production"
  PORT: "3000"

Nämä voidaan injektoida podeille ympäristömuuttujina (env) tai liittää tiedostoina tiedostojärjestelmään (volumes). Secret-resurssi toimii samalla tavalla, mutta tiedot ovat oletuksena Base64-enkoodattuja ja pääsyä niihin voi rajoittaa tarkemmin.

7. PersistentVolume – Pysyvä tallennustila

Kontin paikallinen tiedostojärjestelmä tyhjenee, kun kontti käynnistyy uudelleen. Pysyvää dataa (kuten tietokannat) varten käytetään abstraktioita:

  • PersistentVolume (PV): Klusterin ylläpitäjän tai pilvipalvelun varaama fyysinen levyresurssi.
  • PersistentVolumeClaim (PVC): Podin tekemä "pyyntö" tietyn kokoiselle tallennustilalle, joka liitetään automaattisesti vapaana olevaan PV-resurssiin.

8. Tärkeimmät kubectl-komennot

Klusteria hallitaan komentoriviltä kubectl-työkalulla, joka kommunikoi Control Planen API-palvelimen kanssa.

# Sovella YAML-manifestit klusteriin
kubectl apply -f deployment.yaml

# Tarkastele klusterin resursseja
kubectl get pods
kubectl get services
kubectl get nodes

# Lue podin tiedot ja tapahtumaloki (virheenkorjaus)
kubectl describe pod <podin-nimi>
kubectl logs <podin-nimi>

# Poista resurssi
kubectl delete -f deployment.yaml

Yleisin käytäntö on hallita määrityksiä versionhallinnassa (Git) deklaratiivisesti ja ajaa ne klusteriin kubectl apply -komennolla tai automatisoidulla GitOps-työkalulla.

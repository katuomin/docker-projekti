Mikä Terraform on?

Terraform on infrastruktuurin koodina (Infrastructure as Code, IaC) käytettävä työkalu. AWS-ympäristö kuvataan Terraform-tiedostoissa, ja Terraform vertaa kuvausta nykyiseen ympäristöön. Näin samoja resursseja voidaan luoda ja päivittää toistettavasti komentoriviltä.

  • terraform init alustaa hakemiston ja lataa tarvittavan AWS-providerin.
  • terraform plan näyttää, mitä Terraform aikoo luoda, muuttaa tai poistaa.
  • terraform apply toteuttaa suunnitelman AWS-tilillä hyväksynnän jälkeen.
  • terraform destroy poistaa Terraformin hallinnoimat resurssit.

Terraformin state-tiedosto yhdistää koodissa määritellyt resurssit AWS-resursseihin. Älä muokkaa sitä käsin tai lisää sitä versionhallintaan. Älä myöskään tallenna AWS-avaimia Terraform-tiedostoihin.

Miten tämä projekti käynnistyy?

Tämän projektin Terraform-esimerkki luo EC2-virtuaalikoneen. Käynnistyksen yhteydessä asennusskripti asentaa Dockerin, kloonaa projektin GitHubista ja suorittaa olemassa olevan Docker Compose -kokoonpanon.

  1. Terraform luo EC2-instanssin ja sitä suojaavan security groupin.
  2. EC2:n user data -skripti asentaa Dockerin ja Gitin.
  3. Skripti kloonaa projektin valitun Git-haaran ja suorittaa docker compose up -d --build.
  4. Docker Compose käynnistää web-sivun, nginx-proxyn, notes-API:n ja PostgreSQL-tietokannan.

Selain käyttää nginx-proxyä HTTP-portissa 80. Proxy välittää /api/-pyynnöt notes-API:lle, joten API:n porttia ei tarvitse avata internetiin.

Käynnistä AWS Academy Learner Labissa

Rajoitettua Learner Lab -tiliä varten projektissa on oma terraformlearnerlab/-hakemisto. Se käyttää tilin oletus-VPC:tä ja valmiiksi luotuja LabInstanceProfile- ja vockey-asetuksia. Se ei yritä luoda omaa VPC:tä tai IAM-rooleja.

1. Tarkista vaatimukset

  • Asenna Terraform (vähintään 1.5) ja AWS CLI.
  • Käynnistä AWS Academy Learner Lab ja valitse AWS Details → Show.
  • Projektin GitHub-repositorion ja valitun haaran pitää olla julkisesti kloonattavissa.

2. Aseta Learner Lab -tunnukset

Kopioi kohdasta AWS Details → Show → AWS CLI arvot AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY ja AWS_SESSION_TOKEN. Käytä ensisijaisesti WSL-/bash-terminaalia samassa istunnossa, jossa ajat Terraformia.

export AWS_ACCESS_KEY_ID="<Access key>"
export AWS_SECRET_ACCESS_KEY="<Secret key>"
export AWS_SESSION_TOKEN="<Session token>"
export AWS_REGION="us-east-1"
aws sts get-caller-identity

Vaihtoehtona voit tallentaa tunnukset tiedostoon ~/.aws/credentials profiilin [default] alle:

[default]
aws_access_key_id=<Access key>
aws_secret_access_key=<Secret key>
aws_session_token=<Session token>

Jos käytät PowerShelliä, vastaavat muuttujat voi asettaa muodossa $env:AWS_ACCESS_KEY_ID="...". Labin tunnukset vanhenevat istunnon päättyessä, joten hae tarvittaessa uudet arvot.

3. Alusta ja tarkista Terraform

Aja komennot projektin juurihakemistosta. Terraform valitsee tässä hakemistossa olevan Learner Lab -kokoonpanon:

cd terraformlearnerlab
terraform init
terraform validate
terraform plan

Tarkista suunnitelmasta, että luotavat resurssit ovat odotetut. Oletuksena alue on us-east-1 ja instanssityyppi t3.small.

4. Luo resurssit ja avaa sivu

terraform apply

Hyväksy suunnitelma kirjoittamalla yes. Ensimmäinen käynnistys asentaa ohjelmat ja rakentaa kontit, joten odota muutama minuutti. Avaa tämän jälkeen Terraformin tulostama web_url tai tarkista se komennolla:

terraform output -raw web_url

Hyödyllisiä valintoja

  • Oletuksena repositoriohaara on main. Käytä toista haaraa näin: terraform apply -var="repository_branch=terraformtesti". Varmista, että haluamasi Docker- ja verkkokonfiguraation muutokset on pushattu valittuun haaraan.
  • Security group sallii oletuksena liikenteen internetistä. Rajaa sekä HTTP- että SSH-yhteydet omaan IP-osoitteeseesi esimerkiksi näin: terraform apply -var="allowed_cidr=203.0.113.10/32" (vaihda esimerkkiosoite omaan julkiseen IP-osoitteeseesi).
  • Jos Learner Lab -tililläsi ei ole valmiita profiilia tai avainparia, voit kokeilla: terraform apply -var="instance_profile_name=" -var="key_name=". Tällöin SSH-yhteys ei ole käytettävissä.

Tiedostot tässä esimerkissä

  • main.tf – hakee oletus-VPC:n ja Ubuntu-levykuvan sekä luo EC2-instanssin ja security groupin.
  • variables.tf – määrittää alueen, instanssityypin, Git-haaran ja muut valinnat.
  • user-data.sh.tftpl – asennusskripti, joka valmistelee koneen ja käynnistää Compose-palvelut.
  • outputs.tf – näyttää sivun URL-osoitteen ja SSH-yhteyskomennon.
  • versions.tf – määrittää Terraform- ja AWS-provider-vaatimukset.
  • terraform.tfstate – paikallinen resurssitila; pidä se omana tiedostonasi äläkä commitoi sitä.

Siivoa resurssit käytön jälkeen

EC2-instanssi ja sen julkinen IP voivat aiheuttaa kustannuksia, vaikka et käyttäisi sovellusta. Poista resurssit samasta terraformlearnerlab/-hakemistosta:

terraform destroy

Hyväksy poisto kirjoittamalla yes. PostgreSQL-data on instanssin levyllä ja häviää, kun instanssi poistetaan.
